# DISTRIBUTION FILE → ENCYCLOPEDIA INTEGRATION PLAN (REV. 2)
## How the 247-page in-universe artifact maps into the reference volume

**Source:** `sources/distribution_file_fulltext.txt` (247 pp, structure per its own contents page and `universe_memory/04_STORY_CANON_DIGEST.md`)
**Governing constraint:** Publication plan targets a 480–600 pp single volume at 7×10, with an IngramSpark hardcover ceiling of 840 pp (`encyclopedia_project/01_PUBLICATION_PLAN.md` §1, §5).

**Revision note (Pass 2).** The Pass 1 recommendation (excerpts in the standard edition; full facsimile in a collector slipcase) is superseded per author review in `OPEN_DECISIONS.md` item 2: *"Part of the point of the reference books is to have all information secure in one place. Having what the trilogy defines as the most important information in a separate, detached slipcase where it can get lost or separated from the whole may not be the best idea."* **The default plan is now full in-book integration of the Distribution File in every edition.** The detached facsimile survives only as an optional collector *prototype* — pending physical prototypes and a non-IngramSpark vendor — and nothing in the standard plan depends on it.

## 1. What the Distribution File is, editorially

Three properties drive the strategy:

1. **It is already designed as a document, not prose.** Running footer (f = 111.2 Hz), front-matter telemetry block, five parts with page ranges, chapter cross-keys to the trilogy ("The chapter references locate each part within the events of the Masters X Trilogy. The distribution file is the artifact those chapters describe" — *DF* contents page). Bound in-book as **Part Two**, it should be set as a facsimile-styled insert — its own folios, footer, and CC0 page preserved — so it reads as an artifact *inside* the reference volume rather than as more chapters of it.
2. **It is in-universe CC0.** The fictional public-domain dedication ("The file cannot be un-released. That was the point," *DF* p. ii) removes all narrative friction from a full in-book reprint: the encyclopedia is simply doing what the artifact's own license invites. The author's one-place principle and the artifact's own logic agree.
3. **Its parts map unevenly onto encyclopedia sections.** Parts I and III are reference-dense and partially duplicated by the encyclopedia's analytic entries and Frequency Tables Appendix; Parts II and IV are the most artifact-flavored; the Appendix is raw data. The in-book plan handles this by *placement and headnotes*, not omission.

## 2. Standard plan — full in-book integration (Part Two, all editions)

**Budget.** The full DF is 247 source pages. Reset at 7×10 with the encyclopedia's text block (larger page than the artifact's implied trim), a faithful facsimile-styled resetting lands at approximately **200–230 encyclopedia pages**. Against the current Draft 2 inventory (front matter 12–16 · Part One entries, projected 220–260 at full ~120–150 entry count · Part Three essays 70–90 · apparatus 60–80), a full-DF volume totals roughly **560–680 pp** — above the 480–600 target's midpoint but comfortably under the 840 pp IngramSpark ceiling (plan §5). **The one-place principle is worth the overage.** If the layout pass runs hot, trim from Part One's second-tranche entry count, not from the artifact.

## 3. Collector edition — options, prototypes pending

The collector edition differentiates by **materials and extras, not by content hostage-taking** — the standard edition already contains everything.

- **Option A (default, no new vendor):** same full in-book DF, upgraded case materials, ribbon marker, tip-in signature plate. Entirely within IngramSpark capabilities.
- **Option B (prototype track):** Option A **plus** a duplicate detached DF facsimile in a slipcase pocket — the reading copy stays bound in the book; the facsimile is a redundant artifact object, so nothing can be "lost from the whole." Requires a non-IngramSpark printer for the slipcase/saddle-stitch component (RFQ per plan §8.6). **Status: prototypes pending; author sign-off required; do not schedule against it** (`OPEN_DECISIONS.md` item 2; `CANON.md` §4 TODO 5).
