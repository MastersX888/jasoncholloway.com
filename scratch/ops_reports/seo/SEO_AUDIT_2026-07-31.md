## 1. Executive Summary

### Overall health

| Site | Grade | One-line assessment |
|---|---|---|
| **jasoncholloway.com** | **B / Good foundation, correctness bugs** | Genuinely strong technical SEO — clean canonicals, valid sitemap, correct 404 handling, per-page Book schema, real long-form content, GA4 installed. Undermined by social-metadata inheritance bugs, a stale/orphaned `/blog/` tree, and schema fields that violate Google's Book spec. |
| **seventhcitypress.com** | **D / Functionally broken** | The imprint site exists to deliver a press kit, and **every one of its five press-kit PDFs returns 404**. Its richest structured data never reaches crawlers. It has **no analytics whatsoever**. Three indexable pages total. |

### The single most important finding

`.gitignore` line 48 contains `*.pdf`. Every press-kit PDF on the imprint site is therefore untracked in git, never reaches the Cloudflare Pages build, and 404s in production — including the file listed in the site's own XML sitemap. The imprint site's entire reason for existing is currently non-functional, and it has been shipping dead download links to any journalist, reviewer, or bookseller who visited.

### What's genuinely working (do not "fix" these)

- HTTPS, `www` → apex, and `http` → `https` all resolve in **single-hop 301s**. No redirect chains anywhere tested.
- Trailing-slash canonicalisation is consistent: `/about` → `308` → `/about/`, matching `trailingSlash: true` and the canonical tags.
- Soft-404s do not exist — `/this-page-does-not-exist-seo-test/` returns a true **HTTP 404** plus `<meta name="robots" content="noindex">`.
- `/chapters-sent/` (lead-magnet thank-you page) is correctly `noindex, nofollow` and correctly excluded from the sitemap.
- Every image tested across all 44 crawled pages has an `alt` attribute — **zero missing alt text**, including all 181 folio images on the visualizer. This is unusually good.
- The two domains do **not** cannibalise each other. Measured text overlap between the imprint homepage and the author homepage is a Jaccard of 0.020. The imprint site deliberately passes catalog authority outward to `jasoncholloway.com`. That architecture is correct — keep it.
- The author site already ranks **#2 for "Masters X Trilogy"** and **#2 for "The Inheritance of Frequency"**, and the imprint site ranks **#1 for "Seventh City Press"**. Branded search is essentially solved.

### Honest headline on competitive position

Branded discovery works. Unbranded discovery effectively does not exist and, for a two-month-old indie imprint with no reviews and no backlink profile, will not exist for competitive thriller terms within this planning horizon. The realistic growth surface is the long-tail research content (`/field-notes/`, `/chamber/`), which is already the strongest asset on either domain and is currently under-linked and under-instrumented. The most valuable near-term work is **fixing what is broken and measuring what is already ranking**, not chasing new keywords.

## 2. Method & Evidence Base

- 44 live URLs fetched as raw HTTP (Python `urllib`, browser UA, no JS execution) and parsed with a custom HTML head/heading/link/JSON-LD extractor. Raw HTML and parsed output cached under `scratch/_seo_cache/`.
- Raw response headers captured for every request, including no-follow-redirect probes to observe `Location` headers directly.
- `robots.txt` and `sitemap.xml` retrieved and read in full from both domains.
- Duplicate-content measured by 8-word shingle Jaccard similarity on body text with nav/header/footer/script stripped.
- Local source cross-referenced in the monorepo to pin exact fix locations; `git ls-files` and `git check-ignore` used to confirm deploy-drift root causes.
- Live SERP position spot-checked via web search for branded, title, and entity queries.
- Current guidance verified against Google Search Central's Book structured-data documentation rather than recalled from memory.

### What could not be verified from this machine (stated plainly)

| Item | Why | How to close |
|---|---|---|
| TLS certificate chain validity | The local machine has an intercepting root CA (`Basic Constraints of CA cert not marked critical`), so all verification was disabled. This is a workstation condition, not a site defect. | Check from an uninstrumented network or SSL Labs. |
| Google Search Console verification status | No `google-site-verification` meta tag exists on either domain, but GSC also accepts DNS TXT and Google Analytics verification, which are invisible externally. | Log in to GSC and confirm both properties. |
| Core Web Vitals field data (CrUX) | Requires PageSpeed Insights / CrUX API access. TTFB and payload size were measured; LCP, INP, and CLS were not. | Run PSI on the five money pages. |
| Actual index coverage counts | `site:` operators are unreliable through this search interface. | GSC Pages report. |
| Brotli compression | The crawler advertised only `gzip, deflate`, so `br` was never offered. Absence of Brotli is **not** a finding here. | Re-test with `Accept-Encoding: br`. |

#### P0-1 · All five press-kit PDFs 404 on seventhcitypress.com

**Evidence — live HEAD requests, all five files:**

```
https://seventhcitypress.com/press-kit/Masters_X_Press_Kit.pdf      -> 404
https://seventhcitypress.com/press-kit/Masters_X_Press_Release.pdf  -> 404
https://seventhcitypress.com/press-kit/Masters_X_Fact_Sheet.pdf     -> 404
https://seventhcitypress.com/press-kit/Holloway_Author_Bios.pdf     -> 404
https://seventhcitypress.com/press-kit/Masters_X_Synopses.pdf       -> 404
```

The files **do exist locally** at `seventhcitypress/public/press-kit/`. Root cause confirmed:

```
$ git check-ignore -v seventhcitypress/public/press-kit/Masters_X_Press_Kit.pdf
.gitignore:48:*.pdf     seventhcitypress/public/press-kit/Masters_X_Press_Kit.pdf

$ git ls-files seventhcitypress/public/press-kit | Measure-Object
Count : 0
```

A global `*.pdf` ignore rule means the PDFs are untracked, never reach the Cloudflare Pages Git build, and are absent from the deployed `out/` directory.

**Impact.** The imprint site's homepage links to these files **six times**, including the primary hero CTA "Download Press Kit (PDF)" and a five-tile press-kit section. The site-wide footer links to it on every page. The contact page links to it. `Masters_X_Press_Kit.pdf` is also listed in `sitemap.xml`, so Google is being actively pointed at a 404. Every journalist, reviewer, librarian, or bookseller who has tried to download the press kit since launch has hit a dead link. For an imprint whose entire public site is a press kit, this is total functional failure.

**Fix.** In `.gitignore`, replace the blanket `*.pdf` on line 48 with a negation for the press-kit directory:

```gitignore
*.pdf
!seventhcitypress/public/press-kit/*.pdf
```

Then `git add -f seventhcitypress/public/press-kit/*.pdf`, commit, and redeploy the `seventhcitypress` Pages project. Verify all five URLs return `200` with `content-type: application/pdf` before closing.

**Files:** `.gitignore` (line 48) · `seventhcitypress/public/press-kit/` (5 files to track)

#### P0-2 · The imprint homepage's Book, Person, and WebPage schema never reaches crawlers

**Evidence.** The live homepage contains exactly **one** `application/ld+json` block, holding only `WebSite` and `Organization` — the block emitted by `layout.tsx` as a raw `<script>`:

```json
[{"@context":"https://schema.org","@graph":[
  {"@type":"WebSite","@id":"https://seventhcitypress.com/#website", ...},
  {"@type":"Organization","@id":"https://seventhcitypress.com/#organization", ...}]}]
```

But `seventhcitypress/app/page.tsx` defines a six-node graph — `Person`, `Organization`, three `Book` entities with ISBNs, and a `WebPage`. It is injected via `next/script`:

```185:189:seventhcitypress/app/page.tsx
      <Script
        id="press-jsonld"
        type="application/ld+json"
        dangerouslySetInnerHTML={{ __html: JSON.stringify(jsonLd) }}
      />
```

`next/script` with no `strategy` prop defaults to `afterInteractive`, which injects the tag **client-side after hydration**. It is absent from the static HTML export. The contrast is diagnostic: the same file's `layout.tsx` uses a plain `<script>` and *does* appear live.

**Impact.** The publisher's site serves **zero Book markup** to crawlers. Googlebot may eventually render it, but Bingbot, social scrapers, and AI crawlers will not. The imprint is invisible as a publisher-of-record entity in structured data.

**Fix.** Replace the `<Script>` element with a plain `<script>` tag (matching the pattern already used correctly in `layout.tsx`) and drop the now-unused `import Script from "next/script"` on line 2:

```tsx
<script
  type="application/ld+json"
  dangerouslySetInnerHTML={{ __html: JSON.stringify(jsonLd) }}
/>
```

Corrected graph content is supplied in §6.

**File:** `seventhcitypress/app/page.tsx` (lines 2, 185–189, and the `jsonLd` const at 23–110)

#### P1-4 · Twitter/X card metadata is the global site default on ~20 pages

**Evidence.** `/books/`, `/about/`, `/contact/`, `/returns/`, `/sitemap/`, `/books/hawkes-monograph/`, `/books/books-like-foucaults-pendulum/`, `/books/masters-x/`, all four `/chamber/` pages, and all seven `/blog/` posts emit page-specific `og:title` and `og:description` but fall back to the site-wide Twitter tags:

```html
<meta name="twitter:title" content="Jason Carroll Holloway: Masters X Trilogy">
<meta name="twitter:description" content="Beneath Kansas City's SubTropolis, a fired security guard inherits 30 years of classified research...">
<meta name="twitter:image" content="https://jasoncholloway.com/opengraph-image">
```

On `/books/hawkes-monograph/`, for example, `og:title` is correctly "Innocence, Desire, and the Architecture of the Fall" while `twitter:title` says "Jason Carroll Holloway: Masters X Trilogy". The book detail pages and field notes **do** override correctly — so the pattern is known, just inconsistently applied.

**Impact.** Every share of the Hawkes monograph, the trilogy hub, the Chamber tools, or any essay on X renders the same generic homepage card. Given that X is an active channel (35 posts published 2026-07-30), this directly suppresses click-through on the imprint's most-used social surface.

**Fix.** In Next.js metadata, `twitter` does not inherit from a page's `openGraph` — it inherits from the parent layout's `twitter`. Either add an explicit `twitter: { title, description, images }` to each page's metadata export, or, better, centralise it: build a small `buildMetadata()` helper in `lib/` that derives `twitter` from the same title/description/image inputs as `openGraph`, and route every page through it.

**Files:** each `app/**/page.tsx` listed above · recommend new `lib/seo/metadata.ts`

#### P1-7 · Book schema omits a Google-required property and misformats another

**Evidence** — live JSON-LD from `/books/masters-x/the-inheritance-of-frequency/`:

```json
{
  "@type": "Book",
  "@id": "https://jasoncholloway.com/books/masters-x/the-inheritance-of-frequency#work",
  "name": "Masters X: The Inheritance of Frequency",
  "author": { "@id": "https://jasoncholloway.com/#person" },
  "publisher": { "@id": "https://jasoncholloway.com/#organization" },
  "inLanguage": "English",
  "workExample": [ ... ]
}
```

Checked against Google Search Central's Book documentation:

| Property | Spec | Live value | Verdict |
|---|---|---|---|
| `url` | **Required** | absent | ✗ missing |
| `inLanguage` | ISO 639-1 two-letter code | `"English"` | ✗ invalid, should be `"en"` |
| `image` | Recommended | absent | ✗ missing |
| `datePublished` | Recommended | absent | ✗ missing |
| `description` | Recommended | absent | ✗ missing |
| `bookFormat` | Must be full schema.org URL | `https://schema.org/Paperback` | ✓ correct |
| `isbn` | ISBN-13, per edition | all three correct | ✓ correct |
| `workExample` | Required | present, 3 editions | ✓ correct |

The three ISBNs on Volume I (`9798256008048` PB, `9798295800801` HC, `9798256008819` EPUB) and the Kindle ASIN `B0H4KYMSM1` all match the catalog registry exactly. **The identifiers are right — the wrapper is incomplete.**

Note also that the imprint site's source uses `bookFormat: "Paperback"` as a bare string, which Google ignores; it must be the full URL. Fix that when applying P0-2.

**Honest caveat on payoff.** Google's "Book Actions" rich result (the *Get this book* panel) requires a **submitted data feed** with a root `DataFeed` entity, not on-page markup alone, plus manual eligibility approval. On-page Book markup will not by itself produce that panel. It remains worth fixing — it drives entity understanding, Knowledge Panel accuracy, and AI-assistant answers — but it should not be sold internally as "this will give us rich snippets."

```5:12:app/robots.ts

    rules: { userAgent: "*", allow: "/" },
```

**Assessment, stated precisely because the distinctions matter.** This is a **business decision, not a bug**, and blocking AI training crawlers is a defensible position for a novelist. But the specific consequences are worth knowing:

- **Does not affect Google Search or AI Overviews.** Those use Googlebot; `Google-Extended` only governs Gemini training.
- **Does not block ChatGPT search.** That uses `OAI-SearchBot` and `ChatGPT-User`, neither of which is disallowed. `GPTBot` is the training crawler.

**Fix.** Review the Cloudflare AI Crawl Control setting per domain and decide deliberately. At minimum, consider allowing `Amazonbot`. Note that `/ops/` is disallowed on the author site but returns 404 — harmless, though the rule can be dropped.

### Tier 4 — Structural competitive note

`zvab.com` (AbeBooks Germany) currently **outranks jasoncholloway.com** for `9798256072704` and for the Volume I hardcover ISBN query. This is normal: distributor aggregators inherit domain authority and auto-generate an ISBN page per edition. It is not a failure of the site, and it cannot be beaten by on-page work alone. What *can* be done is ensure that when a reader lands on ZVAB, the metadata there is correct and points home — which is an IngramSpark metadata task, not a website task.

### Where the actual leverage is

For this business, the highest-return "SEO" activity is not keyword targeting. It is:

1. **Reviews.** Zero ratings on Everand and Goodreads is the single largest conversion and ranking handicap. An ARC campaign via NetGalley (already in the project registry) moves more revenue than any technical fix in this document.
2. **The research content as a link magnet.** The folio visualizer and the 111 Hz note are legitimately citable by Voynich-interest communities, archaeoacoustics researchers, and Kansas City history writers. That is the realistic backlink path for an indie imprint.
3. **Entity consolidation.** Wikidata → Open Library → Google Books → `sameAs` alignment is what produces a Knowledge Panel, and a Knowledge Panel is worth more than three page-one rankings for a named author.
